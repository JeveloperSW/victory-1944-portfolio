# 기술 아키텍처

한국어 | [English](ARCHITECTURE.en.md)

## 핵심 판단

가장 어려운 문제는 렌더링 엔진이 아니라 권위 상태, 시간 기반 명령, 경제 원장, 전투 재현, 시즌 운영이다. 현재 VictoryWars의 웹/Electron 자산은 프로토타입 참고 자료로 사용할 수 있지만 `localStorage`와 클라이언트 게임 루프를 온라인 권위 상태로 재사용하지 않는다.

## 논리 구조

1. 모바일 클라이언트: 화면 렌더링, 입력, 로컬 캐시, 접근성, 리플레이 표시
2. API·인증: 계정, 세션, 버전, 요청 검증, 속도 제한
3. 게임 애플리케이션: 도시, 생산, 연구, 군단, 월드, 연맹, 시즌
4. 전투 시뮬레이터: 순수 결정론적 계산 모듈
5. 작업 처리기: 예약 완료, 이동 도착, 알림, 시즌 전환
6. 관계형 DB: 계정, 소유권, 경제 원장, 명령, 전투 메타데이터
7. Redis 계열: 캐시, 분산 잠금, 랭킹, 단기 큐 보조
8. 오브젝트 저장소·분석: 상세 로그, 리플레이, 운영·제품 이벤트
9. 관리자 도구: 조회, 제재, 보상, 설정, 감사

초기 백엔드는 모듈러 모놀리스로 시작한다. 서비스 경계와 운영 병목이 측정되기 전에는 마이크로서비스로 분리하지 않는다.

## 권위 경계

클라이언트는 의도만 전송한다. 서버가 자원 잔액, 생산 가능 여부, 완료 시각, 이동 거리, 피해, 보상, 재고, 영토, 시즌 점수, 결제 지급을 판정한다. 클라이언트 시계·난수·저장값은 권위 증거가 아니다.

## 명령 처리

모든 상태 변경 명령은 인증, 권한, 현재 버전, 선행 조건, 비용, 중복 키를 검증한다. 경제 차감과 명령 생성은 하나의 트랜잭션으로 처리한다. 재시도 가능한 요청에는 idempotency key를 요구하고 동일 키가 다른 payload로 재사용되면 거부한다.

## 전투 재현

전투 입력에는 양측 부대 스냅샷, 장교·교리, 지형·보급, 규칙 버전, 난수 시드가 포함된다. 시뮬레이터는 외부 시간·DB·네트워크에 의존하지 않는 순수 모듈이어야 한다. 결과 해시와 주요 이벤트를 저장하고 과거 규칙 버전으로 재생할 수 있어야 한다.

## 시간과 작업

건설·연구·이동은 매초 모든 객체를 갱신하지 않고 시작 시각과 완료 시각으로 표현한다. 읽기 또는 예약 작업 실행 시 서버 시간을 기준으로 상태를 확정한다. 작업은 적어도 한 번 실행될 수 있다고 가정하고 멱등적으로 처리한다.

## 데이터와 경제

- 잔액만 저장하지 않고 원장에 원인, 이전·이후 값, 요청·운영자 식별자를 남긴다.
- 자원은 음수가 될 수 없고 이중 지급이 없어야 한다.
- 순위·캐시는 재생성 가능해야 하며 DB의 권위 상태를 대체하지 않는다.
- 스키마 변경은 호환 배포 순서와 복구 계획을 포함한다.
- 시즌 초기화는 삭제보다 새 season_id와 보관 정책을 우선한다.

## 현재 PoC 구현 경계

- `engine/`은 시간·DB·네트워크에 의존하지 않는 순수 규칙 모듈이며 전투 결과와 구조화 분석을 같은 입력·규칙 버전·seed로 재현한다.
- `server/` schema v4는 SQLite 한 파일에서 건설 상태에 병력 재고, 작전 영수증·원장, 정찰 보고서, NPC 전투 입력·보고서를 additive table로 연결하고, v5는 도시의 경제 규칙과 캠페인 규칙 버전을 별도 열로 결속한다. 비용·병력·도시 version·보고서·영수증은 한 트랜잭션에서 확정한다.
- 건설과 작전은 actor·commandId를 전역 멱등 키로 공유하고, 다른 명령 종류의 같은 키 재사용도 거부한다. 저장 전투 보고서는 캠페인·전투 규칙 버전, 정찰 FK, canonical 입력, 재계산 결과 hash, 사상자·원장과 교차 검증한다. 작전 조회와 멱등 재생은 전체 병력 이력 및 건설·작전 통합 자원 원장에 등장한 자원의 잔액 연쇄를 현재 상태와 대조한다. 초기 배정 원장이 없는 자원은 첫 변경 전까지 이 연쇄만으로 원점을 증명할 수 없다.
- 로컬 프로토타입 화면은 Bearer 토큰 HTTP 경로와 압축 시계 건설 워커를 루프백에서 조작하는 내부 하네스다. DB 옆 파일에 epoch·hour 길이를 고정하고 정확한 루프백 Host와 동일 Origin만 허용하며 정상 종료 시 세션 토큰을 폐기한다. 비정상 종료 토큰 회수, 토큰 만료, HTTPS, 공개 배포 보안, 다중 호스트 또는 실제 이용자 검증의 증거가 아니다.
- SQLite 어댑터만 검증됐다. PostgreSQL은 방언별 migration, BIGINT 정규화, snapshot 격리, 명령별 잠금·경합 의미를 실제 인스턴스에서 검증하기 전까지 구현 완료로 간주하지 않는다.

## 클라이언트 기술 선택

두 경로를 기술 검증한다.

- 웹 자산 재사용: TypeScript + 2D 렌더러(PixiJS 계열) + Capacitor
- 전용 엔진: Unity 등 모바일 게임 엔진

선택 기준은 기존 자산 재사용률, 2D 월드·리플레이 성능, 결제·푸시·스토어 SDK, 팀 역량, 빌드 안정성, 장기 유지비다. 어느 경로든 서버 API와 전투 규칙의 권위 경계는 동일하다.

## 관측 가능성

요청 ID, 계정 ID, 월드·시즌, 명령 ID, 전투 ID, 규칙 버전을 구조화 로그에 연결한다. 지표는 오류율, 지연, 작업 적체, 경제 생성·소모, 중복 거부, 전투 실패, 결제 검증, 신고 처리 시간을 포함한다. 개인정보와 비밀값은 로그에 남기지 않는다.
